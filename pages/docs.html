🌐 Network & Security

NAT Traversal

The system uses a 3-layer approach to guarantee connectivity on any network.

🌐 NAT Traversal Layers Diagram
Placeholder: nat-traversal.png - Visual diagram showing UDP hole punch → TCP hole punch → Relay proxy flow
全
Method Speed Success Rate When Used
UDP Hole Punch 5-20ms 70-95% Home networks, most routers
TCP Hole Punch 10-30ms 85-98% When UDP is blocked
Relay Proxy 50-200ms 100% Corporate firewalls, all networks
💡 The system automatically tries methods in order: UDP → TCP → Relay. You will always connect!

🔧 Troubleshooting

🔴 "Can't connect to server" +

Solution:

  • Windows: Get-Service RemoteControlServer
  • Linux: systemctl status remotecontrol or ps aux | grep python
  • macOS: launchctl list | grep remotecontrol or ps aux | grep python
  • Check firewall: Allow port 5000
  • Verify IP address and network connectivity: ping <server_ip>
🔧 Firewall Configuration
Placeholder: firewall-config.png - Shows firewall rule configuration
🔐 "Authentication failed" +

Solution: Reset the admin password:

.\secure_server.ps1 -ResetPassword   # Windows
./secure_server.sh --reset-password  # Linux/macOS

The new password will be displayed. Save it immediately!

🐌 "High latency / slow response" +

Solution:

  • Check which connection method is being used (UDP is fastest, Relay is slowest)
  • Reduce screen quality in server config: "screen_quality": 50
  • Use direct IP connection if possible
  • Check network bandwidth: iperf3 -c <server_ip>
🍎 "macOS: Screen Recording not working" +

Solution: Grant screen recording permission:

  1. Open System Settings → Privacy & Security
  2. Select Screen Recording
  3. Add your terminal app (Terminal, iTerm2, etc.)
  4. Restart the terminal app

🐧 "Linux: xdotool not found" +

Solution: Install xdotool:

# Ubuntu/Debian
sudo apt install xdotool

# Fedora/RHEL
sudo dnf install xdotool

# Arch Linux
sudo pacman -S xdotool
🪟 "Windows: Service won't start" +

Solution:

  • Check logs: Get-Content "C:\Program Files\RemoteControlServer\logs\server.log" -Tail 50
  • Verify port is not in use: netstat -an | findstr :5000
  • Restart service: Restart-Service RemoteControlServer
  • Reinstall service: .\remote_service.ps1 -Mode uninstall; .\remote_service.ps1 -Mode install

❓ Frequently Asked Questions

Can I control multiple computers? +

Yes! Add multiple servers to favorites in client_config.json. The server supports up to 10 concurrent connections.

Is this secure over the internet? +

Yes. All traffic is encrypted with TLS + Fernet. Authentication is required. Rate limiting prevents brute force attacks. The system follows zero-trust principles.

Does this work on Linux/Mac? +

Yes! Both client and server work on Linux and Mac with Python 3.8+ installed. Input emulation uses xdotool/pyautogui (Linux) and Quartz (macOS).

How much bandwidth does it use? +

Approximately 1-5 MB per minute depending on screen activity. Screen quality settings can reduce bandwidth usage.

Can I transfer files? +

File transfer is supported but disabled by default for security. Enable in server_config.json: "file_transfer": true

What's the difference between local and cloud mode? +

Local mode uses direct connections (faster, 5-20ms). Cloud mode uses Netlify relay (works anywhere, 50-200ms). The system automatically selects the best method.

Is there a mobile app? +

Planned for v2.1. Currently works on desktop browsers via web client and any device with Python support.

How do I update the system? +

Pull the latest code and rebuild packages:

git pull origin main
.\scripts\build_separate_packages.ps1
.\deploy_server.ps1 -PackagePath .\deploy\RemoteControl_Server_v2.0.0.zip -RegisterService
